# Meteor Survival

Asteroids for the Game Boy (DMG), written in GBDK-2020 C with no game engine.
One game source file, one generated tile header, and a Super Game Boy border.
Same lineage as the sibling `GB-*` projects: procedural art from a Python
script, and the toolchain run out of a shared Docker image when GBDK is not
installed.

Controls: **LEFT/RIGHT** rotate, **A** thrust, **B** fire, **START** begins.

## Build

    make          # meteor.gb
    make probe    # headless PyBoy checks against the built ROM (implies sym)
    make usage    # ROM/RAM headroom
    make gfx      # regenerate gfx.h from gen_gfx.py (committed)
    make border   # regenerate the SGB border from tools/mkborder.py (committed)
    make sym      # a -debug build: meteor.map carries every symbol, not just globals
    make image    # build the gbdk-dev Docker image (only needed once)
    make clean

**GBDK is not needed on the host.** `make` falls back to the shared `gbdk-dev`
Docker image the sibling projects use, so it works with no setup as long as that
image exists. `GBDK_HOME=~/path make` uses a real toolchain instead if you have
one. Neither Python nor PyBoy is needed to build or play: `make` on its own
produces the ROM with no Python at all, and `make probe` is dev-only.

## Files

| File | What it is |
|---|---|
| `meteor.c` | Everything that touches hardware: ship, bullets, rocks, collisions, waves, lives, HUD, SFX |
| `gfx.h` | Generated, committed — the ship, bullet, rock and explosion tiles |
| `gen_gfx.py` | Generates `gfx.h`; replace with real art using the same tile layout |
| `tools/probe_ramp.py` | Headless emulator checks: the difficulty ramp, and the ship's death explosion |
| `tools/mkborder.py` | Generates `art/border_sgb.png`, the Super Game Boy border, with self-checks |
| `art/border_sgb.png` | Generated, committed — the 256x224 border art |
| `sgb_border.c` / `.h` | The SGB border transfer, lifted verbatim from the sibling projects |
| `border_data.c` / `.h` | Generated by `make border`, committed — the border's tiles, map and palette, in bank 1 |

## The game

The ship rotates, thrusts and wraps at all four screen edges; rocks split once
into two of the next size down and score by size, small rocks scoring most. The
screen is a fixed 160x144 that wraps, and every position is a `uint16_t` in 8.8
fixed point whose high byte is the pixel.

Difficulty ramps on two axes, both driven by the wave number alone: the count of
large rocks (`2 + wave`, saturating at the pool's 8) and their speed. Count
alone plateaus almost immediately, so speed is the real lever. Wave 1 is
deliberately left untouched by the ramp.

**The ship explodes rather than vanishing.** It comes apart into four shards
thrown out on the diagonals, reusing its own OAM slot plus the three the sprite
budget leaves spare — 1 ship + 4 bullets + 8 rocks x 4 tiles is 37 of the DMG's
40, so there was nowhere else to take them from.

## The Super Game Boy border

On a Super Game Boy the game is framed by a scene of asteroids and a starfield,
drawn rather than painted: `tools/mkborder.py` generates `art/border_sgb.png` the
way `gen_gfx.py` generates the tiles, and `make border` turns it into
`border_data.c/.h` with png2asset. `meteor.c` hands the three blobs to
`set_sgb_border()` once at boot.

Three things about it are traps, and each is commented where it bites:

- **`-Wm-ys`** puts the SGB flag in the ROM header. Without it the SGB silently
  discards the border packets — no error, and identical behaviour on a DMG, so
  it is invisible everywhere except on the real thing.
- **The transfer trashes VRAM.** It stages its artwork through the same tiles
  the font and sprites came from, so the game's own tile loads are repeated
  afterwards. An ordinary Game Boy skips the whole block on `sgb_check()`.
- **A border of exactly 128 tiles transfers nothing** (the count shifts left into
  a `uint8_t`). 256 is the SGB's ceiling. `mkborder.py` asserts against both,
  along with the 16-colour palette limit.

**No automated check covers the border's pixels.** PyBoy emulates a DMG, where
`sgb_check()` is false and every line of the border path is skipped, so the
artwork is owed to an eyeball in an emulator with SGB emulation on. What
`probe_ramp.py` asserts is the header flag and nothing else.

## Testing

`tools/probe_ramp.py` boots the ROM headless under PyBoy and asserts on the
game's own statics, which it reads out of the linker map by hardcoded WRAM
address. It checks that the ramp actually ramps, and kills the ship on purpose
to check that it breaks into four shards, mirrored on both axes and all four
distinct.

There is no host-side unit test: `meteor.c` includes `gb/gb.h`, so plain gcc
cannot compile it. Pulling the hardware-independent rules into a `sim.h`, as the
sibling projects do, is what would enable one.

## Release

The ROM is never committed — `*.gb`, the linker map and the object files are all
gitignored. Attach a built `meteor.gb` to a release instead.
